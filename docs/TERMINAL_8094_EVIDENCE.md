## 1. F1 — `preset` 是死参数（契约失真）

OpenAPI 为 `/api/pick` 声明了 `preset` 参数，实测传入 6 个不同预设（底部三绝 / 放宽 ADX / 盘中选股 / 强势选股 / 月底选股 / 临时选股）与不传参数，**返回首元素完全相同**。前端实际做法是把 `PRESETS[v]` 填入 `#cond-input`，再以 `conds` 提交——即预设完全靠前端字符串，后端 `preset` 参数不消费。契约声明与实现不一致，调用方按契约使用会得到错误预期。

## 2. F2 — 无效 `conds` 静默回退（决策误导，最高危）

| `conds` | 实测 |
|---|---|
| `cci_w>99`（有效） | 返回不同结果（`sh600323`）→ 通道本身可用 |
| `1/0` | HTTP 200，**回退到默认选股结果** |
| `__import__('os').getcwd()` | HTTP 200，回退到默认结果（未被执行，注入面已挡） |
| `cci_w`（裸标识符） | HTTP 200，回退到默认结果 |
| `""` / `close>0 or 1==1` | HTTP 200，回退到默认结果 |
| `cci_w>99;1/0` | HTTP 200，结果与 `cci_w>99` **完全相同**（无效项被静默丢弃） |
| `cci_w>99,cci_m>99` | HTTP 200，退化为默认结果（逗号不是合法分隔符） |
| `cci_w>99 AND cci_m>99` / `(cci_w>99)` / `cci_w>>99` | HTTP 200，退化为默认结果 |
| `unknown_field>1` / `cci_w>abc` | HTTP 200，退化为默认结果 |

**精确机制（避免夸大）**：上游按分号 `;` 逐条解析表达式，遇到无法解析的项**静默丢弃**；当所有项都无效时，退化为默认公式选股结果。因此：
- 用户写了 3 条条件、其中 1 条拼错 → 系统按 2 条执行并返回 200，不提示少了 1 条；
- 用户整条写错 → 拿到默认选股清单，首元素恒为 `sz000851 *ST高鸿`，看起来像正常结果。

这是"静默错误"而非"显式失败"：不报错、不返回 4xx、不携带任何警告，使用者会误以为自己写的条件全部生效。**公平性说明**：`conds` 通道本身有效（合法表达式返回不同结果），前端预设正是把 6 个公式字符串填入 `#cond-input` 再以 `conds` 提交，所以缺陷不是"公式选股不能用"，而是"失败时无反馈 + 无声降级"。注入型字符串未被求值（无 RCE 迹象），此项不构成安全漏洞。

## 5. F5 — 前向收益口径未披露（算法自洽、可独立复算）

> **更正说明**：本节早期版本标题为「前向收益无法用同接口日线复算」，系错误推断，现按反推结果重写。正确结论是：**算法自洽、三个周期均可独立复算**；真实缺口是「口径未在契约披露」＋「日线硬截断导致全量复算不可行」。

用 `/api/stock/sz300398?days=999999` 的日线按 `c[t+h]/c[t]-1` 自算，与 `/api/signals` 的 `fwd_h` 平均相差约 0.7 个百分点（收盘到收盘口径平均绝对误差 0.0070~0.0073）。改用 **T+1 开盘**作为买入基准后误差收敛到四位小数舍入量级：

| 周期 h | 可复核样本 n | `c[t+h]/o[t+1]-1` 平均绝对误差 | 最大绝对误差 | 收盘到收盘口径平均绝对误差 |
|---|---|---|---|---|
| 5 | 413 | 2.335e-05 | 4.952e-05 | 0.007021 |
| 20 | 412 | 2.505e-05 | 4.996e-05 | 0.007093 |
| 60 | 407 | 2.510e-05 | 4.995e-05 | 0.007317 |

即 **`fwd_h = close[t+h] / open[t+1] - 1`**，价格基准为 T+1 开盘；残差来自接口输出的四位小数舍入，不是算法不一致。契约（`openapi.json`）与响应体均**未披露**该公式、价格基准与有效样本数（`fwd_disclosed_in_contract=false`），调用方无从知道胜率按什么价格计算——这才是 F5 的缺陷本体。

另有一处独立缺口：单股日线**硬截断在 2,000 根**（首根 2018-08-16，末根 2026-11-17），但 `meta.universe_start=2015-06-01`，窗口与元数据不一致；`days=999999` 仍只返回 2,000 根且产生 449,253 B 响应。因此**全量历史独立复算不可行**（列演进项，需解除截断），但可见窗口内的逐条复算已经通过。规整层本期只补口径披露，不改算法、不重算收益、不标「不可复算」。

## 8.1 口径维度陷阱（数据工程组纠正，禁止混用）

同一个字符串 `G1` 在三个接口里是**三种不同维度的量**，做相等判定或交叉引用会直接产生假结论：

| 出现位置 | 含义 | 维度 | 实测值 |
|---|---|---|---|
| `/api/stock/{code}` → `groups.G1` | 该股**当日**是否命中 G1 | 布尔（单股·单日） | `false` |
| `/api/signals/{code}?group=G1` → `total` | 该股**历史**信号事件数 | 时序计数（单股·全历史） | `515` |
| `/api/stats` → `G1` | **当日全市场**命中只数 | 横截面计数（全市场·单日） | `576` |

同理 `/api/scan?group=G7` 的 `total=26` 是当日横截面命中只数，`/api/stats.touch_n=576`、`dead_n=4668`、`narrow_n=1106` 也都是当日横截面量。任何断言都不得把 515、576、26、4668 互相比较或要求相等。
