② 八类改造点 · 事实 / 口径 / 影响

F1 · preset 是死参数（契约失真）

Could 契约层问题，不是功能故障
事实
OpenAPI 为 /api/pick 声明 preset（params=['conds','limit','market','preset']）。实测传入 6 个不同预设与不传参数，返回首元素完全相同，distinct=1。
口径
前端实际做法是把 PRESETS[v] 填入 #cond-input，再以 conds 提交；后端 preset 参数不消费。前端 6 个预设可用，公式选股通道本身有效。
影响
契约声明与实现不一致，按契约接入的第三方（U3）会得到错误预期；主受害方仅 U3，RICE 0.4。

F2 · 无效 conds 静默回退 最高危 · P0 阻断

「静默错误」而非「显式失败」：不报错、不返回 4xx、不携带任何警告。
事实
5 个无效 / 注入型 conds（1/0、__import__('os').getcwd()、裸 cci_w、空串、close>0 or 1==1）全部 HTTP 200 且回退默认选股结果，n=5 all_default=True。
精确机制
上游按分号 ; 逐条解析，无法解析的项静默丢弃；全部无效时退化为默认公式选股清单，首元素恒为 sz000851 *ST高鸿（收盘 0.38 元）。cci_w>99;1/0 与 cci_w>99 结果完全相同；逗号 / AND 关键字静默退化。注入型字符串未被求值，不构成安全漏洞。
影响
使用者误以为所写条件全部生效：写 3 条拼错 1 条 → 按 2 条执行返回 200；整条写错 → 拿到默认清单。有效 cci_w>99 返回不同结果 sh600323，证明通道可用。
上述个股代码为历史统计样例，非推荐。缺陷定位：失败时无反馈 + 无声降级，不是「公式选股不能用」。

F5 · 前向收益口径反推（可复算，缺口在披露）

主理人裁决 4 第 1 条更正：F5 不是「不可复算」，改造建议为补披露，不是改算法、也不是标 UNVERIFIABLE。
verified_formula : fwd_h = close[t+h] / open[t+1] - 1
口径含义       : 信号次日开盘（T+1 open）买入，持有 h 日后收盘
三周期样本     : n = 413 / 412 / 407   （h = 5 / 20 / 60）
T+1 开盘口径   : 最大绝对误差 4.996e-05 （仅 4 位小数舍入）
收盘到收盘口径 : 平均误差约 0.007      （0.007021 / 0.007093 / 0.007317）
算法自洽可复算，缺口是未披露 + 日线截断 2000 根。 fwd_disclosed_in_contract=false（OpenAPI schema 为空、无字段说明）；单股日线硬截断在 2,000 根， 首根 2018-08-16、末根 2026-11-17，而 meta.universe_start=2015-06-01 —— 历史窗口与元数据不一致，且 days=999999 仍只返回 2,000 根。
早期用收盘到收盘口径自算时多处相差 0.7~1.2 个百分点（如 2026-11-10 自算 -0.0566 / 接口 -0.0448，差 -0.0118），曾疑似算错；全样本反推确认是口径不同，非计算错误。

⑤ 改造方案摘要

实施序（按依赖拓扑，非 RICE 分数）

F6 · 统一信封 / 参数边界→ F8 · disclaimer 全量注入→ F2 · INVALID_CONDS 显式失败→ F4 · 双口径并置→ F3 · 缺失值 / ST 过滤
